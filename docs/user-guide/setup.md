# Setup

Install QDash with Docker Compose, then sign in as its initial administrator.

The sections from [Prepare the Host](#prepare-the-host) to
[Verify the Installation](#verify-the-installation) are required, in order. AI, the default color
theme, several deployments on one host, and remote access are optional and can be added later.

## Choose a Backend

| Goal | Backend |
| --- | --- |
| Evaluate QDash without quantum hardware | [Fake](./setup/fake-backend.md); no backend configuration before startup |
| Operate a Qubex-connected lab deployment | [Qubex](./setup/qubex-backend.md); place the Qubex configuration before startup |
| Connect another hardware stack | Not supported by deployment settings, which accept only `fake` and `qubex`; an additional backend requires QDash code changes. |

The backend determines the available calibration tasks and hardware connection.

To change QDash code and run the API or UI on the host, use
[Development Environment Setup](../developer-guide/setup.md).

## Prepare the Host

Install Git, Docker, and Docker Compose. Go Task is optional; every required setup command has a
Docker Compose equivalent.

Clone the stable branch. The repository default is `develop`, so select `main` explicitly:

```bash
git clone --branch main https://github.com/oqtopus-team/qdash.git
cd qdash
```

The `main` branch contains stable releases. Do not use `develop`, a feature branch, or a
prerelease tag for an operational installation. Follow [System Updates](./system-updates.md) to
move an existing installation to another release.

## Create the Environment File

Every deployment reads its settings from `.env` in the checkout. Create it from the example for
the chosen backend.

For Fake, copy the default example and keep its backend values:

```bash
cp .env.example .env
```

```dotenv
ENV=dev-fake
DEFAULT_BACKEND=fake
```

Fake needs no other backend configuration before startup. [Fake backend](./setup/fake-backend.md)
explains what the simulator runs.

For Qubex, copy the Qubex example:

```bash
cp .env.example.qubex .env
```

Prepare the configuration root at `CONFIG_PATH` before startup. Place existing chips' hardware
and parameter files there as described in [Qubex backend](./setup/qubex-backend.md). You can
create a new chip's configuration after signing in.

## Configure Shared Deployment Settings

Set a unique initial administrator password in `.env` before starting QDash. The
other values in the example work unchanged for a first local start.

| Variable | Purpose |
| --- | --- |
| `QDASH_ADMIN_USERNAME` / `QDASH_ADMIN_PASSWORD` | Initial administrator login |
| `ENV` | Name of the deployment, also used as the Docker Compose project name |
| `UI_PORT` | Port that browsers use for the UI, the API, and Prefect; the only port QDash opens on the host |
| `MONGO_DATA_PATH` / `POSTGRES_DATA_PATH` | Persistent database directories |
| `CALIB_DATA_PATH` | Calibration figures, raw data, and run artifacts |
| `CLIENT_URL` | Public UI URL used in links generated by QDash; an `https://` URL makes redirects for its host use HTTPS |
| `NEXT_PUBLIC_DEFAULT_THEME` | Initial UI theme for browsers without a saved preference; see [Set the Default Color Theme](#set-the-default-color-theme) |

The example files also list optional AI provider, Slack, knowledge repository, and tunnel
settings. Leave an optional credential empty when that integration is not in use.

## Start QDash

Validate the resolved Compose configuration, then build and start the enabled services:

```bash
docker compose config --quiet
docker compose up -d --build
```

If Go Task is installed, `task deploy-local` performs the startup and also pulls the optional
knowledge repository configured by `KNOWLEDGE_REPO_URL`.

Application logs use Docker named volumes, which normal container recreation preserves.

## Verify the Installation

Confirm that the containers are running:

```bash
docker compose ps
```

Open these pages on `UI_PORT` from `.env`:

- QDash UI: <http://localhost:5714/login>
- API documentation: <http://localhost:5714/api/docs>
- Prefect: <http://localhost:5714/prefect/dashboard>

QDash opens only `UI_PORT` on the host. The API, Prefect, MongoDB, PostgreSQL, mongo-express,
and the deployment service are reachable only from the other QDash containers.
[Operations](./operations.md#open-a-database-shell) shows how to open a database shell.

On the QDash UI sign-in page, enter `QDASH_ADMIN_USERNAME` and `QDASH_ADMIN_PASSWORD` and select
**Sign in**. QDash creates this administrator on first start with a default project that the
administrator owns, and opens **Execution** in that project. If the containers or the sign-in page
do not come up, see [Operations](./operations.md#check-service-health).

## Optional Settings

Add these settings to `.env` when the deployment needs them.

### Configure AI

<a id="authenticate-ai-endpoints-with-cloudflare-access"></a>

AI chat and figure analysis need model endpoints in `.env`. [AI Setup](./setup/ai.md) covers the
endpoints, the optional classifier, and Cloudflare Access service tokens.

### Set the Default Color Theme

Set `NEXT_PUBLIC_DEFAULT_THEME` to `light`, `dark`, `cupcake`, `emerald`, `corporate`,
`synthwave`, `nord`, `night`, `dracula`, `dim`, `abyss`, `business`, `coffee`, or `sunset`.
An unsupported value falls back to `light`.

A theme selected from **Settings** is saved in the browser and takes precedence. This variable is
embedded in the UI image at build time; rebuild the UI after changing it:

```bash
docker compose build ui
docker compose up -d ui
```

### Run Several Deployments on One Host

Give each deployment its own checkout and `.env`, with a different `ENV` and `UI_PORT`. Leave the
other port settings as they are; they do not open host ports. `ENV` and `UI_PORT` keep the
containers and ports apart but not the data: keep the default data directories inside each
checkout, or set `MONGO_DATA_PATH`, `POSTGRES_DATA_PATH`, and `CALIB_DATA_PATH` to different
directories for each deployment.

### Enable Remote Access

Set `CLIENT_URL` to the public UI URL, set `TUNNEL_TOKEN`, and enable the `tunnel` Compose profile.

```dotenv
CLIENT_URL=https://qdash.example.com
TUNNEL_TOKEN=<cloudflare-tunnel-token>
COMPOSE_PROFILES=tunnel
```

Start the stack again with `docker compose up -d --build`. `task deploy` is the equivalent Go
Task command; it enables the tunnel while preserving profiles already configured in `.env`.
