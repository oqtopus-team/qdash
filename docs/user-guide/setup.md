# Setup

Choose the backend before configuring QDash: Fake runs without quantum hardware, while Qubex
connects QDash to a supported lab system.

## Choose a Backend

| Goal | Setup path |
| --- | --- |
| Evaluate QDash without quantum hardware | [Fake backend](./setup/fake-backend.md) |
| Operate a Qubex-connected lab deployment | [Qubex backend](./setup/qubex-backend.md) |
| Connect another hardware stack | Under construction — the current release accepts only `fake` and `qubex`; another backend requires QDash code changes, not deployment settings. |

Both supported paths use the same Docker Compose stack. The backend choice changes the available
calibration tasks and whether the workflow worker opens a hardware connection.

Host-side API and UI processes are a development workflow. Use
[Development Environment Setup](../developer-guide/setup.md) instead of this page when changing
QDash code.

## Prepare the Host

Install Git, Docker, and Docker Compose. Go Task is optional; every required setup command has a
Docker Compose equivalent.

Clone the stable branch. The repository default is `develop`, so select `main` explicitly:

```bash
git clone --branch main https://github.com/oqtopus-team/qdash.git
cd qdash
```

The `main` branch contains stable releases. Do not use `develop`, a feature branch, or a
prerelease tag for an operational installation. Follow [System Updates](./system-updates.md) to
move an existing installation to another release.

Next, complete either the [Fake backend](./setup/fake-backend.md) or
[Qubex backend](./setup/qubex-backend.md) configuration. Each path creates the `.env` file used by
the remaining steps.

## Configure Shared Deployment Settings

Set a unique initial administrator password in `.env` before exposing QDash to a network.

| Variable | Purpose |
| --- | --- |
| `QDASH_ADMIN_USERNAME` / `QDASH_ADMIN_PASSWORD` | Initial administrator login |
| `API_PORT` / `UI_PORT` / `PREFECT_PORT` | Host ports for the API, UI, and Prefect |
| `MONGO_DATA_PATH` / `POSTGRES_DATA_PATH` | Persistent database directories |
| `CALIB_DATA_PATH` | Calibration figures, raw data, and run artifacts |
| `PREFECT_UI_URL` | Prefect UI URL for the sidebar link and API flow run links. When empty, the sidebar link uses the host that served QDash at `PREFECT_PORT`, and flow run links use `http://localhost:<PREFECT_PORT>` |
| `PREFECT_UI_API_URL` | API URL the Prefect UI calls from the browser; defaults to `/api` so the UI works from other machines |
| `CLIENT_URL` | Public UI URL used in links generated by QDash |
| `NEXT_PUBLIC_DEFAULT_THEME` | Initial UI theme for browsers without a saved preference |

Prefect is reachable from other machines at `http://<host>:<PREFECT_PORT>`, but not through the
Cloudflare tunnel domain. If an older `.env` sets `NEXT_PUBLIC_PREFECT_URL` to a `localhost` URL,
replace it with `NEXT_PUBLIC_PREFECT_URL=${PREFECT_UI_URL}` and rebuild the UI image so the sidebar
link works from other machines.

The example files also list optional AI provider, Slack, knowledge repository, and tunnel
settings. Leave an optional credential empty when that integration is not in use.

### Enable the Pi Agent Runtime

The Pi Agent Runtime is an optional Compose service. Enable it only when the deployment uses the
Pi Copilot backend:

```dotenv
COMPOSE_PROFILES=agent-runtime
AGENT_RUNTIME_TOKEN=<random-shared-secret>
```

Leave `COMPOSE_PROFILES` unset for the in-process `litellm` backend. Set
`AGENT_RUNTIME_ENABLE_WRITE_TOOLS=true` only in a trusted experimental deployment. QDash still
requires the signed-in user to approve each proposed write in the chat.

Multiple profiles use a comma-separated value, such as `agent-runtime,tunnel`.

### Set the Default Color Theme

Set `NEXT_PUBLIC_DEFAULT_THEME` to `light`, `dark`, `cupcake`, `emerald`, `corporate`,
`synthwave`, `nord`, `night`, `dracula`, `dim`, `abyss`, `business`, `coffee`, or `sunset`.
An unsupported value falls back to `light`.

A theme selected from **Settings** is saved in the browser and takes precedence. This variable is
embedded in the UI image at build time; rebuild the UI after changing it:

```bash
docker compose build ui
docker compose up -d ui
```

## Start QDash

Validate the resolved Compose configuration, then build and start the enabled services:

```bash
docker compose config --quiet
docker compose up -d --build
```

If Go Task is installed, `task deploy-local` performs the startup and also pulls the optional
knowledge repository configured by `KNOWLEDGE_REPO_URL`.

Application logs use Docker named volumes. The Pi runtime stores resumable conversation state in
the `agent-runtime-state` volume. Normal container recreation preserves both.

## Verify the Installation

Confirm that the containers are running:

```bash
docker compose ps
```

Open these services using the ports from `.env`:

- QDash UI: <http://localhost:5714/login>
- API documentation: <http://localhost:5715/docs>
- Prefect: <http://localhost:4200>

Sign in with `QDASH_ADMIN_USERNAME` and `QDASH_ADMIN_PASSWORD`. For a Fake deployment, continue
with [Running Calibrations](./running-calibrations.md). For Qubex, confirm the intended chip and
hardware configuration before starting a task.

## Enable Remote Access

Set `CLIENT_URL` to the public UI URL, set `TUNNEL_TOKEN`, and enable the `tunnel` Compose profile.
Keep `agent-runtime` in the comma-separated value when Pi is enabled:

```dotenv
CLIENT_URL=https://qdash.example.com
TUNNEL_TOKEN=<cloudflare-tunnel-token>
COMPOSE_PROFILES=agent-runtime,tunnel
```

Start the stack again with `docker compose up -d --build`. `task deploy` is the equivalent Go
Task command; it enables the tunnel while preserving profiles already configured in `.env`.
